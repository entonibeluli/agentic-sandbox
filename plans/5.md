# Plan for #5: Enable the metrics endpoint in the deployment

## Goal
Enable the existing metrics listener in Kubernetes on port 9100, expose it as a named `metrics` container port, and document how operators can reach it. Keep the application metrics implementation and HTTP API behavior unchanged.

## Dependencies (confirmed / plausible / open), each with change: yes | no
- confirmed: `src/config.ts` — `METRICS_ENABLED` and conditional `METRICS_PORT` already validate the runtime contract. change: no
- confirmed: `src/server.ts` — the metrics listener starts when enabled and serves plain-text metrics. change: no
- confirmed: `k8s/configmap.yaml` — currently disables metrics; set `METRICS_ENABLED=true` and provide `METRICS_PORT=9100`. change: yes
- confirmed: `k8s/deployment.yaml` — currently exposes only the `http` container port; add a named `metrics` port at 9100. change: yes
- confirmed: `k8s/service.yaml` — currently exposes only HTTP; add a named metrics service port so the documented port-forward path is stable. change: yes
- confirmed: `README.md` — environment and operations documentation must explain the enabled port and access command. change: yes
- confirmed: `test/app.test.ts` — config validation already covers the metrics prerequisite; no application test change is required. change: no
- plausible: `.github/workflows/ci.yml` — deployment gates consume the manifests but should not need edits; verify through the pipeline. change: no
- open: none; the ticket defines the required deployment port and documentation outcome.

## Tests
- Existing config tests continue to cover metrics enablement and required port validation.
- Pipeline deployment checks must confirm rollout, smoke, and browser checks remain green with the second listener.
- No new browser test is required because the page uses only the HTTP port.

## Environment contract
`METRICS_ENABLED=true` and `METRICS_PORT=9100` will be added to `k8s/configmap.yaml`; both variables already exist in `src/config.ts` and the README environment table. No new variable is introduced.

## Risks
- A missing or mismatched `METRICS_PORT` causes startup failure; keep it distinct from HTTP port 3000.
- Incorrect container/service port names or targets can make metrics unreachable while the main app remains healthy.
- The extra listener must not interfere with rollout, stability, smoke, or browser checks.
- Kubernetes manifest behavior can only be fully verified by the pipeline’s ephemeral kind deployment.

## Open questions
None.

## Decisions
- Use port 9100 for the metrics listener.
- Expose the port as `metrics` on both the Deployment container and Service.
- Document `kubectl port-forward service/sandbox-app 9100:metrics` as the access path.
- Implemented in `k8s/configmap.yaml`, `k8s/deployment.yaml`, `k8s/service.yaml`, and `README.md`.
